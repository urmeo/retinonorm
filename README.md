# CortexProbe

**Population receptive fields and lesion effects in convolutional models of the visual hierarchy.**

Status: instrument validated, no network probed yet. Every number below is generated from a
recorded run in this repository and re-checked in CI. No result is claimed that has not been
measured.

---

## What this is

A measurement instrument for **population receptive fields (pRFs) in convolutional networks**.

In human fMRI, a voxel's pRF is estimated by sweeping a bar aperture across the visual field and
regressing the voxel's timecourse against candidate 2D Gaussians (Dumoulin & Wandell, 2008,
*NeuroImage* 39:647-660). That procedure applies unchanged to a convolutional unit: present the
same stimulus, record the unit's activation timecourse, fit the same model. The output is a
*measured* pRF for an artificial unit, in the same units as the human quantity.

Once units have pRFs, two things become possible that a plain encoding model cannot do:

- **Lesion a network and measure the consequence.** Silence units in an early layer, refit
  downstream pRFs, and quantify the distortion — an artificial scotoma.
- **Treat architectural variation as individual difference.** Independently seeded instances
  give different pRF maps; the spread is measurable and testable against fit noise.

### Why it is built this way

Two neighbouring projects stall on the same wall: they require authorised restricted data (HCP
7T, NSD) before a single empirical number can exist, so neither reports one. CortexProbe has no
such dependency. Stimuli are generated in-repo; the "brain" is a frozen network. Every number
here is producible, reproducible, and defensible on a laptop.

### Scope boundary

A frozen ImageNet-trained CNN is **not** a biologically realistic model of visual cortex. It has
no recurrence, no separate excitatory and inhibitory populations, and no built-in cortical
magnification. This project does not claim otherwise. It builds the measurement apparatus that
biologically realistic architectures would need in order to be evaluated. This boundary is not
softened anywhere in this repository.

## Design decisions

**Unit-volume Gaussians.** The receptive field is normalised by `1 / (2 * pi * sigma**2)`, so a
wide pRF spreads the same total weight more thinly rather than accumulating more of it. Under
unit-peak normalisation every pRF would share a maximum of 1.0, its overlap with the aperture
would grow with sigma by construction, and the hypothesis that pRF size increases with depth
would be guaranteed by the parameterisation instead of measured.

**Sigma is bounded at both ends, for the same reason.** Unit volume is a property of the
continuous Gaussian, and the grid only approximates it. Below the pixel pitch the Gaussian is
under-sampled: at `sigma = 0.2` it sums to 0.031 for a pRF centred on a pixel, and to 0.160 or
0.350 as the centre moves a quarter or a half pixel off-lattice. Above roughly `resolution / 6`
it is truncated by the field edge instead: on a 64 px field, `sigma = 20` retains 0.723 of its
volume and `sigma = 40` retains 0.275. The ceiling is the more dangerous of the two, because the
shortfall grows with sigma and so biases exactly the axis pRF size against depth is measured on.
The configuration rejects a floor under 1 px; the fitter, which is the only place that knows both
the bound and the field size, rejects a ceiling that keeps less than 0.99 of unit volume.

**Amplitude is never searched, but its sign is checked.** At each trial position, amplitude and
baseline are solved in closed form by linear least squares, so the nonlinear optimiser explores
only `x0`, `y0`, `sigma`. That keeps the search three-dimensional and removes a family of local
minima. It also admits negative amplitudes: a unit whose response *falls* where the aperture
covers a location fits a flawless pRF there with the sign reversed. Surround suppression and
normalisation both produce such units, so a negative amplitude is not accepted as a pRF.

**Convergence and acceptance are different questions.** `converged` is the optimiser's report
that the search terminated. `accepted` is the scientific claim that the unit has a measurable
pRF: converged, above the R² threshold, positive amplitude, and sigma not pinned against its
search ceiling. A centre pinned at the edge of the visual field stays accepted, because real
receptive fields sit there; a pinned sigma does not, because that value records where the search
stopped rather than what the data support.

**Folds split by sweep axis, never by frame.** Adjacent frames within a sweep show near-identical
apertures, so a random frame split places near-duplicates on both sides of the train/test
boundary and reports memorisation as generalisation. Measured below. The group is the sweep
*axis*, not the direction: the bar position depends on `x cos θ + y sin θ`, which negates under a
180° turn, while the sweep offsets are symmetric about zero, so a direction and its opposite
produce bit-identical frames. Without an HRF there is no temporal asymmetry to tell them apart,
so a return sweep carries nothing its outbound partner does not. Wedge and ring groups come from
index arithmetic that knows nothing about how much neighbouring apertures share, so frames that
overlap a training frame above `max_fold_similarity` are measured and dropped when the sequence
is built.

**Misspecification is reported, not hidden.** A single Gaussian cannot represent a unit driven by
two separated lobes; it settles on one, reports a sigma belonging to neither, and still clears
the R² threshold. Each fit therefore carries `second_field_r2`, the variance a second receptive
field would explain on top of the first. Genuine single-lobed units stay under 0.03 from noiseless
to 80 % noise; two-lobe units score 0.29 to 0.44. It is reported rather than enforced, so
downstream analysis picks its own cut and states it.

## Results

**These validate the instrument, not any scientific claim.** No network has been probed. The
four hypotheses this project exists to test — pRF size increasing with depth, size increasing
with eccentricity, lesion-induced downstream distortion, and measurable spread across seeded
instances — are all **untested**. They are experiments, and a negative result will be reported
as a negative result. The scope boundary above applies to everything in this section, and is
repeated in [`results/VALIDATION.md`](results/VALIDATION.md) where the same tables are recorded.

Measured under a 64 px field, 20 steps, four sweep directions, and a coarse grid of 10 with
sigma bounded to [1, 10] px. The configuration digest appears in each table's footer.

`dof = distinct_frames - 5`, since the projected amplitude and baseline are estimated parameters
too, and a frame shown twice is not a second observation.

### Cross-validation and leakage

A first version of the leakage test asserted that a random frame split would inflate scores on
white noise. Measurement showed it does not. The leak requires **two** ingredients: overlapping
apertures *and* a response correlated across neighbouring frames. Real activation timecourses
have both, because a bar moving one step barely changes the input.

<!-- BEGIN GENERATED: cross_validation -->
| Response | n seeds | Grouped CV | Random-split CV | Leak | Leak positive |
|---|---|---|---|---|---|
| White | 20 | -0.248 ± 0.135 | -0.339 ± 0.192 | -0.091 ± 0.231 | 8 / 20 |
| Autocorrelated | 20 | -0.624 ± 0.385 | -0.164 ± 0.189 | +0.459 ± 0.402 | 17 / 20 |

Mean ± SD over seeds 21–40. The carrier is a width-3 boxcar, whose lag-1 autocorrelation measured 0.651 ± 0.086 against a theoretical 0.667.

<sub>Recorded on macOS-26.6.1 arm64, Python 3.12.13, NumPy 2.5.2, SciPy 1.18.0 | config digest `4d6a856a499e` | generated 2026-08-19</sub>

A random frame split raises the apparent score on temporally correlated noise in most
realisations tested, while on white noise the effect is indistinguishable from zero given the
realisation-to-realisation spread. Both cases are tests, so the mechanism stays pinned: if the
white-noise case ever starts leaking too, the cause is aperture overlap rather than response
autocorrelation.

## Install and verify

Python 3.9 or newer, tested on 3.9 and 3.12. The implemented core needs only NumPy and SciPy.
PyTorch becomes necessary at `models.py`, and pandas plus pyarrow at `prf/result.py`; both live
in optional extras until those modules land.

```bash
python3 -m pip install -e '.[dev]'
python3 -m pytest tests -q
python3 benchmarks/benchmark_scaling.py
```

221 tests currently pass. They use synthetic fixtures only and download nothing. The slower
statistical tests — interval coverage over 200 realisations, and the leakage effect over 20
seeds — are marked `slow` and can be deselected with `-m 'not slow'`.

### Reproducing these numbers

Every table in the Results section is generated, not written. The script that produces them also
splices them into this file, so the two cannot drift apart:

```bash
python3 scripts/generate_validation_report.py
```

It writes [`results/validation.json`](results/validation.json) and
[`results/VALIDATION.md`](results/VALIDATION.md), each carrying the platform, library versions and
configuration digest the numbers came from. To verify the committed tables without rewriting
anything:

```bash
python3 scripts/generate_validation_report.py --check
```

That re-measures everything and compares it against the committed record within a tolerance far
tighter than any figure displayed, then confirms the tables were rendered from those numbers
rather than edited by hand. CI runs it on both supported Python versions. Every measurement
except the runtime table reproduces unchanged across Python 3.9 to 3.12 and across NumPy and
SciPy versions; timings are hardware-specific and are refreshed only with `--runtime`.

## Testing strategy

The central risk is a fitter that returns confident nonsense, so the suite is built around
proving it does not.

| Suite | What it establishes |
|---|---|
| `test_config.py` | Every validation guard fires; digests are stable and sensitive |
| `test_geometry.py` | The coordinate conventions stimuli and pRFs both depend on |
| `test_stimuli.py` | **No held-out frame duplicates or closely resembles a training frame** |
| `test_prf_model.py` | Unit volume; prediction is the overlap it claims to be |
| `test_prf_recovery.py` | Known parameters are recovered; noise is rejected |
| `test_prf_edge_cases.py` | Boundary centres, both sigma bounds, suppression, misspecification |
| `test_prf_uncertainty.py` | Errors scale with noise; interval coverage is calibrated |
| `test_cross_validation.py` | Folds hold out whole groups; the leakage mechanism is pinned |
| `test_prf_designs.py` | Recovery across bar, wedge, ring and across pRF sizes |

The stimulus invariants are asserted against the **default** configuration as well as the smaller
one the rest of the suite uses. An earlier version of this instrument passed every test while the
shipped default placed a verbatim copy of every held-out frame in the training set, because no
test ever built that configuration.
